# 数据库处理逻辑梳理

## 一、数据库架构设计

### 1.1 表结构概览

系统共包含 **5个核心表**：

| 表名 | 说明 | 主键 | 外键关系 |
|------|------|------|----------|
| `department` | 部门表 | DID (CHAR(10)) | - |
| `position_config` | 职务配置表 | PID (CHAR(10)) | - |
| `employee` | 员工表 | EID (INT) | DID → department, PID → position_config |
| `attendance_record` | 考勤记录表 | AID (INT) | EID → employee |
| `application` | 申请表 | AID (INT) | EID → employee, ApproverID → employee |

### 1.2 表结构详细说明

#### 1.2.1 部门表 (department)
```sql
DID CHAR(10) PRIMARY KEY          -- 部门ID，格式：D000000001
DName VARCHAR(30) NOT NULL        -- 部门名称
Description VARCHAR(200)           -- 部门描述
ManagerID INT                      -- 负责人ID（员工ID）
```

**特点**：
- 使用固定格式的字符串ID：`D` + 9位数字
- ManagerID 可为空，表示未指定负责人

#### 1.2.2 职务配置表 (position_config)
```sql
PID CHAR(10) PRIMARY KEY          -- 职务ID，格式：P000000001
PName VARCHAR(20) NOT NULL         -- 职务名称
WorkStartTime TIME NOT NULL        -- 标准上班时间
WorkEndTime TIME NOT NULL          -- 标准下班时间
MonthlyWorkDays INT DEFAULT 21     -- 月工作日
DailyWorkHours DECIMAL(3,1) DEFAULT 8.0  -- 每日工作时长
Description VARCHAR(200)           -- 职务描述
```

**特点**：
- 使用固定格式的字符串ID：`P` + 9位数字
- 存储职务的考勤标准配置

#### 1.2.3 员工表 (employee)
```sql
EID INT AUTO_INCREMENT PRIMARY KEY  -- 员工ID（自增）
DID CHAR(10) NOT NULL               -- 部门ID
PID CHAR(10) NOT NULL               -- 职务ID
EName CHAR(20) NOT NULL             -- 员工姓名
Sex CHAR(2)                         -- 性别：'男'/'女'
Phone CHAR(11) UNIQUE               -- 联系电话（唯一）
Password CHAR(20) NOT NULL          -- 登录密码
Role CHAR(10) DEFAULT 'EMPLOYEE'    -- 角色：EMPLOYEE/APPROVER/ADMIN
```

**外键约束**：
- `DID` → `department(DID)` ON DELETE RESTRICT ON UPDATE CASCADE
- `PID` → `position_config(PID)` ON DELETE RESTRICT ON UPDATE CASCADE

**索引**：
- `idx_did (DID)`
- `idx_pid (PID)`
- `idx_role (Role)`

#### 1.2.4 考勤记录表 (attendance_record)
```sql
AID INT AUTO_INCREMENT PRIMARY KEY  -- 考勤记录ID
EID INT NOT NULL                     -- 员工ID
RecordDate DATE NOT NULL             -- 考勤日期
CheckInTime DATETIME                -- 签到时间
CheckInLocation VARCHAR(100)         -- 签到地点
CheckOutTime DATETIME               -- 签退时间
CheckOutLocation VARCHAR(100)        -- 签退地点
Status VARCHAR(20) DEFAULT 'NORMAL'  -- 状态：NORMAL/LATE/EARLY_LEAVE/MISSING
WorkHours DECIMAL(4,2)               -- 工作时长（小时）
```

**外键约束**：
- `EID` → `employee(EID)` ON DELETE CASCADE ON UPDATE CASCADE

**索引**：
- `idx_eid (EID)`
- `idx_date (RecordDate)`
- `UNIQUE KEY uk_employee_date (EID, RecordDate)` - 确保每个员工每天只有一条记录

#### 1.2.5 申请表 (application)
```sql
AID INT AUTO_INCREMENT PRIMARY KEY     -- 申请ID
EID INT NOT NULL                       -- 申请人ID
ApplicationType VARCHAR(20) NOT NULL   -- 类型：LEAVE/REISSUE/OVERTIME/BUSINESS_TRIP
StartTime DATETIME NOT NULL            -- 开始时间
EndTime DATETIME NOT NULL              -- 结束时间
Reason TEXT NOT NULL                   -- 申请原因
Status VARCHAR(20) DEFAULT 'PENDING'   -- 状态：PENDING/APPROVED/REJECTED/CANCELLED
ApproverID INT                         -- 审批人ID
ApproveTime DATETIME                   -- 审批时间
RejectReason TEXT                      -- 拒绝原因
CreatedAt DATETIME DEFAULT CURRENT_TIMESTAMP  -- 创建时间

-- 请假特有字段
LeaveType VARCHAR(20)                  -- 请假类型
Attachment VARCHAR(500)                 -- 附件路径

-- 补卡特有字段
ReissueType VARCHAR(20)                -- 补卡类型
ReissueTime DATETIME                   -- 补卡时间

-- 加班特有字段
OvertimeType VARCHAR(20)                -- 加班类型
IsCompensatory BOOLEAN DEFAULT FALSE    -- 是否调休

-- 出差特有字段
Destination VARCHAR(100)                -- 目的地
Companions VARCHAR(500)                 -- 随行人员（JSON格式）
Transportation VARCHAR(50)               -- 交通工具
Budget DECIMAL(10,2)                    -- 预算金额
```

**外键约束**：
- `EID` → `employee(EID)` ON DELETE CASCADE ON UPDATE CASCADE
- `ApproverID` → `employee(EID)` ON DELETE SET NULL ON UPDATE CASCADE

**索引**：
- `idx_eid (EID)`
- `idx_status (Status)`
- `idx_type (ApplicationType)`
- `idx_created (CreatedAt)`

## 二、DAO层架构设计

### 2.1 设计模式

系统采用 **DAO (Data Access Object) 模式**，使用 **Spring JDBC Template** 进行数据访问。

**架构层次**：
```
Controller → Service → DAO → Database
```

**DAO层特点**：
- 接口与实现分离：`XxxDAO` 接口 + `XxxDAOImpl` 实现类
- 使用 `@Repository` 注解标记为数据访问层
- 使用 `JdbcTemplate` 执行SQL
- 使用 `RowMapper` 进行结果集映射

### 2.2 DAO组件列表

| DAO接口 | 实现类 | 对应实体 | 功能说明 |
|---------|--------|----------|----------|
| `EmployeeDAO` | `EmployeeDAOImpl` | `Employee` | 员工数据访问 |
| `DepartmentDAO` | `DepartmentDAOImpl` | `Department` | 部门数据访问 |
| `AttendanceRecordDAO` | `AttendanceRecordDAOImpl` | `AttendanceRecord` | 考勤记录数据访问 |
| `ApplicationDAO` | `ApplicationDAOImpl` | `Application` | 申请数据访问 |
| `PositionConfigDAO` | `PositionConfigDAOImpl` | `PositionConfig` | 职务配置数据访问 |

## 三、数据访问方法详解

### 3.1 EmployeeDAO - 员工数据访问

#### 3.1.1 查询方法

**`findByEmployeeId(int employeeId)`**
```java
SELECT * FROM employee WHERE EID = ?
```
- 根据员工ID查询单个员工
- 返回 `Employee` 对象，不存在返回 `null`
- 使用 `EmptyResultDataAccessException` 处理空结果

**`findAll()`**
```java
SELECT * FROM employee ORDER BY EID
```
- 查询所有员工，按EID排序

**`findByDepartmentId(Integer departmentId)`**
```java
SELECT * FROM employee WHERE DID = ? ORDER BY EID
```
- 根据部门ID查询该部门所有员工
- **特殊处理**：将数字ID转换为字符串格式（如：`1` → `"D000000001"`）

#### 3.1.2 更新方法

**`insert(Employee employee)`**
```java
INSERT INTO employee (DID, PID, EName, Sex, Phone, Password, Role) 
VALUES (?, ?, ?, ?, ?, ?, ?)
```
- 插入新员工
- 注意：EID是自增的，不需要插入

**`update(Employee employee)`**
```java
UPDATE employee SET DID = ?, PID = ?, EName = ?, Sex = ?, Phone = ?, Role = ? 
WHERE EID = ?
```
- 更新员工信息（不包括密码）

**`updatePassword(int employeeId, String newPassword)`**
```java
UPDATE employee SET Password = ? WHERE EID = ?
```
- 单独更新密码

**`updatePhone(int employeeId, String newPhone)`**
```java
UPDATE employee SET Phone = ? WHERE EID = ?
```
- 单独更新电话

**`delete(int employeeId)`**
```java
DELETE FROM employee WHERE EID = ?
```
- 删除员工（会级联删除相关记录）

#### 3.1.3 数据映射逻辑 (EmployeeRowMapper)

**字段映射**：
- `EID` → `Integer` (员工ID)
- `DID` → `String` (部门ID，使用 `trim()` 去除空格)
- `PID` → `String` (职务ID，使用 `trim()` 去除空格)
- `EName` → `String` (姓名)
- `Sex` → `String` (性别)
- `Phone` → `String` (电话)
- `Password` → `String` (密码)
- `Role` → `String` (角色，默认 "EMPLOYEE" 如果字段不存在)

**特殊处理**：
- CHAR类型字段使用 `trim()` 去除尾部空格
- Role字段有容错处理，如果不存在则使用默认值

### 3.3 AttendanceRecordDAO - 考勤记录数据访问

#### 3.3.1 查询方法

**`findByEmployeeIdAndDate(Integer eid, LocalDate date)`**
```java
SELECT * FROM attendance_record WHERE EID = ? AND RecordDate = ?
```
- 查询指定员工指定日期的考勤记录

**`findByEmployeeId(Integer eid)`**
```java
SELECT * FROM attendance_record WHERE EID = ? ORDER BY RecordDate DESC
```
- 查询指定员工的所有考勤记录，按日期倒序

**`findByEmployeeIdAndDateRange(Integer eid, LocalDate startDate, LocalDate endDate)`**
```java
SELECT * FROM attendance_record 
WHERE EID = ? AND RecordDate BETWEEN ? AND ? 
ORDER BY RecordDate DESC
```
- 查询指定员工在日期范围内的考勤记录

**`findByEmployeeIdAndDateRangeAndStatus(Integer eid, LocalDate startDate, LocalDate endDate, String status)`**
```java
SELECT * FROM attendance_record 
WHERE EID = ? AND RecordDate BETWEEN ? AND ? AND Status = ? 
ORDER BY RecordDate DESC
```
- 查询指定员工在日期范围内且状态匹配的考勤记录

**`findByDepartmentIdAndDateRange(Integer departmentId, LocalDate startDate, LocalDate endDate)`**
```java
SELECT ar.* FROM attendance_record ar 
INNER JOIN employee e ON ar.EID = e.EID 
WHERE e.DID = ? AND ar.RecordDate BETWEEN ? AND ? 
ORDER BY ar.RecordDate DESC
```
- **关联查询**：通过员工表关联查询部门下所有员工的考勤记录
- **ID转换**：将数字部门ID转换为字符串格式（`D%09d`）

**`findByDepartmentIdAndDateRangeAndStatus(Integer departmentId, LocalDate startDate, LocalDate endDate, String status)`**
```java
SELECT ar.* FROM attendance_record ar 
INNER JOIN employee e ON ar.EID = e.EID 
WHERE e.DID = ? AND ar.RecordDate BETWEEN ? AND ? AND ar.Status = ? 
ORDER BY ar.RecordDate DESC
```
- 带状态筛选的部门考勤记录查询

**`findAllByDateRange(LocalDate startDate, LocalDate endDate)`**
```java
SELECT * FROM attendance_record 
WHERE RecordDate BETWEEN ? AND ? 
ORDER BY RecordDate DESC
```
- 查询所有员工在日期范围内的考勤记录

**`findAllByDateRangeAndStatus(LocalDate startDate, LocalDate endDate, String status)`**
```java
SELECT * FROM attendance_record 
WHERE RecordDate BETWEEN ? AND ? AND Status = ? 
ORDER BY RecordDate DESC
```
- 带状态筛选的全员考勤记录查询

**`findAll()`**
```java
SELECT * FROM attendance_record ORDER BY RecordDate DESC
```
- 查询所有考勤记录

#### 3.3.2 更新方法

**`insert(AttendanceRecord record)`**
```java
INSERT INTO attendance_record (EID, RecordDate, CheckInTime, CheckInLocation, 
                              CheckOutTime, CheckOutLocation, Status, WorkHours) 
VALUES (?, ?, ?, ?, ?, ?, ?, ?)
```
- **时间转换**：`LocalDateTime` → `Timestamp`（使用 `Timestamp.valueOf()`）

**`update(AttendanceRecord record)`**
```java
UPDATE attendance_record 
SET CheckInTime = ?, CheckInLocation = ?, CheckOutTime = ?, CheckOutLocation = ?, 
    Status = ?, WorkHours = ? 
WHERE AID = ?
```

#### 3.3.3 数据映射逻辑 (AttendanceRecordRowMapper)

**字段映射**：
- `AID` → `Integer` (记录ID)
- `EID` → `Integer` (员工ID)

## 四、数据转换与特殊处理

### 4.1 ID格式转换

#### 4.1.1 部门ID转换
```java
// 数字ID → 字符串ID
String deptIdStr = String.format("D%09d", departmentId);
// 例如：1 → "D000000001"

// 字符串ID → 数字ID（在Service层处理）
String did = employee.getDid(); // "D000000001"
Integer deptId = Integer.parseInt(did.replace("D", "").replaceFirst("^0+", ""));
```

#### 4.1.2 职务ID转换
```java
// 数字ID → 字符串ID
String pidStr = String.format("P%09d", positionId);
// 例如：1 → "P000000001"
```

### 4.2 时间类型转换

#### 4.2.1 LocalDateTime ↔ Timestamp
```java
// Java → Database
Timestamp.valueOf(localDateTime)

// Database → Java
timestamp.toLocalDateTime()
```

#### 4.2.2 LocalDate ↔ Date
```java
// Java → Database
Date.valueOf(localDate)

// Database → Java
rs.getDate("RecordDate").toLocalDate()
```

### 4.3 NULL值处理

#### 4.3.1 使用 wasNull() 判断
```java
int managerId = rs.getInt("ManagerID");
department.setManagerId(rs.wasNull() ? null : managerId);
```

#### 4.3.2 使用 try-catch 处理
```java
try {
    String role = rs.getString("Role");
    employee.setRole(role != null ? role.trim() : "EMPLOYEE");
} catch (SQLException e) {
    employee.setRole("EMPLOYEE");
}
```

### 4.4 CHAR类型空格处理

MySQL的CHAR类型会自动填充空格到指定长度，需要特殊处理：

```java
// 读取时去除空格
String did = rs.getString("DID");
employee.setDid(did != null ? did.trim() : null);

// 查询时使用TRIM
String sql = "SELECT * FROM position_config WHERE TRIM(PID) = ?";
```

## 五、查询模式分析

### 5.1 单表查询

**模式**：直接查询单表
```java
SELECT * FROM employee WHERE EID = ?
```

### 5.2 关联查询

**模式**：使用INNER JOIN关联多表
```java
SELECT ar.* FROM attendance_record ar 
INNER JOIN employee e ON ar.EID = e.EID 
WHERE e.DID = ? AND ar.RecordDate BETWEEN ? AND ?
```

**模式**：使用BETWEEN进行日期范围查询
```java
SELECT * FROM attendance_record 
WHERE RecordDate BETWEEN ? AND ?
```

### 5.4 条件组合查询

**模式**：多个WHERE条件组合
```java
SELECT * FROM application 
WHERE EID = ? AND Status = ? 
ORDER BY CreatedAt DESC
```

### 5.5 排序

**模式**：使用ORDER BY排序
- 考勤记录：按日期倒序 `ORDER BY RecordDate DESC`
- 申请记录：按创建时间倒序 `ORDER BY CreatedAt DESC`
- 员工记录：按ID正序 `ORDER BY EID`

## 六、统计查询逻辑

### 6.1 考勤统计查询

**数据来源**：`attendance_record` 表

**查询维度**：
1. **按员工**：`findByEmployeeIdAndDateRange()`
2. **按部门**：`findByDepartmentIdAndDateRange()` (关联查询)
3. **全部员工**：`findAllByDateRange()`

**时间范围**：
- 周度：本周一至今天
- 月度：本月1号至今天

### 6.2 申请统计查询

**数据来源**：`application` 表

**查询方式**：
1. **按员工**：`findByEmployeeIdAndStatus()`
2. **按部门**：遍历部门下所有员工，合并结果
3. **全部员工**：`findAll()` + 过滤

**统计逻辑**：
- **加班时长**：计算 `StartTime` 到 `EndTime` 的时长（小时）
- **请假人次**：统计申请次数（按日期范围重叠判断）
- **出差人次**：统计申请次数（按日期范围重叠判断）
- **补卡次数**：统计申请次数（按审批时间判断）

**时间判断**：
- 加班：使用申请的 `StartTime` 日期
- 请假/出差：判断申请的日期范围是否与统计范围重叠
- 补卡：使用审批时间 `ApproveTime`

## 七、事务处理

### 7.1 事务管理

系统使用 **Spring 声明式事务管理**，在Service层使用 `@Transactional` 注解。

**事务特性**：
- 默认传播行为：`REQUIRED`
- 默认隔离级别：数据库默认
- 默认回滚：运行时异常和错误

### 7.2 级联操作

**外键级联规则**：
- `employee` → `attendance_record`：`ON DELETE CASCADE`（删除员工时级联删除考勤记录）
- `employee` → `application`：`ON DELETE CASCADE`（删除员工时级联删除申请）
- `employee` → `application.ApproverID`：`ON DELETE SET NULL`（删除审批人时设置为NULL）
- `department` → `employee`：`ON DELETE RESTRICT`（有员工时不能删除部门）
- `position_config` → `employee`：`ON DELETE RESTRICT`（有员工时不能删除职务配置）

## 十、常见问题与解决方案

### 10.1 CHAR类型空格问题

**问题**：CHAR(10)类型在MySQL中会自动填充空格

**解决方案**：
- 读取时使用 `trim()`
- 查询时使用 `TRIM()` 函数

### 10.2 ID格式转换问题

**问题**：前端传递数字ID，数据库存储字符串ID

**解决方案**：
- DAO层进行格式转换：`String.format("D%09d", departmentId)`
- Service层处理格式转换逻辑

### 10.3 时间类型转换问题

**问题**：Java `LocalDateTime` 与数据库 `DATETIME` 类型转换

**解决方案**：
- 使用 `Timestamp.valueOf()` 和 `toLocalDateTime()`

### 10.4 NULL值处理问题

**问题**：数据库NULL值与Java对象null的映射

**解决方案**：
- 使用 `rs.wasNull()` 判断
- 使用 `rs.getObject()` 配合null判断

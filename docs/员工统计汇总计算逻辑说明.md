# 员工统计汇总计算逻辑说明

## 一、概述

员工统计汇总功能用于统计员工的工作时长、加班、请假、补卡等数据。支持**周度**和**月度**两种统计方式。

**重要说明**：员工查询和管理员查询使用**相同的后端计算逻辑**，但前端显示方式不同：
- **员工查询**：只能查看自己的数据，前端固定显示月度数据
- **管理员查询**：可以查看任意员工/部门/全部员工的数据，前端可以根据 `viewType` 选择显示周度或月度数据

## 二、时间范围定义

### 2.1 周度统计
```java
LocalDate now = LocalDate.now();
LocalDate weekStart = now.minusDays(now.getDayOfWeek().getValue() - 1);
// 例如：如果今天是周三（值为3），则 weekStart = 今天 - (3-1) = 本周一
// 统计范围：本周一 00:00:00 至 今天 23:59:59
```

### 2.2 月度统计
```java
LocalDate monthStart = LocalDate.of(now.getYear(), now.getMonth(), 1);
// 统计范围：本月1号 00:00:00 至 今天 23:59:59
```

**注意**：无论是员工查询还是管理员查询，时间范围的计算逻辑都是相同的：
- 周度：本周一至今天
- 月度：本月1号至今天

## 三、本月工作时长计算

### 3.1 数据来源
- **表**：`attendance_record`（考勤记录表）
- **字段**：`WorkHours`（工作时长，单位：小时）

### 3.2 查询逻辑

**单个员工查询**：
```java
monthRecords = attendanceRecordDAO.findByEmployeeIdAndDateRange(employeeId, monthStart, now);
```

**部门查询**：
```java
monthRecords = attendanceRecordDAO.findByDepartmentIdAndDateRange(departmentId, monthStart, now);
// 通过 INNER JOIN employee 表关联查询
```

**全部员工查询**：
```java
monthRecords = attendanceRecordDAO.findAllByDateRange(monthStart, now);
```

### 3.3 计算方式
```java
double monthWorkHours = monthRecords.stream()
    .filter(r -> r.getWorkHours() != null)  // 过滤掉工作时长为空的记录
    .mapToDouble(r -> r.getWorkHours().doubleValue())  // 转换为double
    .sum();  // 求和
```

**关键点**：
- 只统计 `WorkHours` 不为 `null` 的记录
- 对所有记录的工作时长进行求和
- 单位：小时（保留1位小数）

### 3.4 数据说明
- `WorkHours` 字段在打卡时自动计算：`下班时间 - 上班时间`
- 如果只有上班打卡没有下班打卡，`WorkHours` 可能为 `null`

## 四、加班时长计算

### 4.1 数据来源
- **表**：`application`（申请表）
- **申请类型**：`OVERTIME`（加班）
- **状态**：`APPROVED`（已批准）

### 4.2 查询逻辑

**单个员工查询**：
```java
overtimeApps = applicationDAO.findByEmployeeIdAndStatus(employeeId, "APPROVED");
```

**部门查询**：
```java
// 1. 获取部门下所有员工
List<Employee> employees = employeeService.getAllEmployees();
String deptIdStr = String.format("D%09d", departmentId);
List<Integer> employeeIds = employees.stream()
    .filter(emp -> deptIdStr.equals(emp.getDid()))
    .map(Employee::getEid)
    .collect(Collectors.toList());

// 2. 遍历每个员工，查询其已批准申请
overtimeApps = new ArrayList<>();
for (Integer eid : employeeIds) {
    overtimeApps.addAll(applicationDAO.findByEmployeeIdAndStatus(eid, "APPROVED"));
}
```

**全部员工查询**：
```java
List<Application> allApps = applicationDAO.findAll();
overtimeApps = allApps.stream()
    .filter(app -> "OVERTIME".equals(app.getApplicationType()))
    .filter(app -> "APPROVED".equals(app.getStatus()))
    .collect(Collectors.toList());
```

### 4.3 时间过滤逻辑
```java
.filter(app -> {
    LocalDate appDate = app.getStartTime().toLocalDate();  // 获取申请的开始日期
    // 判断申请的开始日期是否在统计范围内
    return !appDate.isBefore(startDate) && !appDate.isAfter(endDate);
})
```

**关键点**：
- 使用申请的 **开始时间（StartTime）的日期** 来判断是否在统计范围内
- 条件：`申请开始日期 >= 统计开始日期 且 申请开始日期 <= 统计结束日期`

### 4.4 时长计算
```java
.mapToDouble(app -> {
    long minutes = Duration.between(
        app.getStartTime(),  // 加班开始时间
        app.getEndTime()      // 加班结束时间
    ).toMinutes();
    return minutes / 60.0;  // 转换为小时
})
.sum();  // 对所有加班时长求和
```

**关键点**：
- 计算每个申请的时长：`结束时间 - 开始时间`（分钟）
- 转换为小时：`分钟数 / 60.0`
- 对所有符合条件的申请时长求和
- 单位：小时（保留1位小数）

### 4.5 示例
假设本月有2个已批准的加班申请：
- 申请1：2024-01-15 18:00 至 2024-01-15 21:00 → 3小时
- 申请2：2024-01-20 19:00 至 2024-01-20 22:30 → 3.5小时
- **本月加班时长**：3 + 3.5 = **6.5小时**

## 五、请假计算

### 5.1 数据来源
- **表**：`application`（申请表）
- **申请类型**：`LEAVE`（请假）
- **状态**：`APPROVED`（已批准）

### 5.2 查询逻辑
与加班查询逻辑相同，只是过滤条件改为：
```java
.filter(app -> "LEAVE".equals(app.getApplicationType()))
```

### 5.3 时间过滤逻辑（重要）
```java
.filter(app -> {
    LocalDate appStartDate = app.getStartTime().toLocalDate();
    LocalDate appEndDate = app.getEndTime().toLocalDate();
    // 检查请假日期是否与统计范围有重叠
    return !appEndDate.isBefore(startDate) && !appStartDate.isAfter(endDate);
})
```

**关键点**：
- 使用**日期范围重叠判断**，而不是单点日期判断
- 条件：`申请结束日期 >= 统计开始日期 且 申请开始日期 <= 统计结束日期`
- 这意味着只要请假日期范围与统计范围有任何重叠，就会被统计

### 5.4 计算方式（两种逻辑）

#### 5.4.1 管理员界面：统计人次
```java
.count();  // 统计申请次数，每人每次申请算1人次
```

**关键点**：
- 统计的是**人次**（申请次数），不是天数
- 每个已批准的请假申请算1人次
- 如果一次请假跨多天，也只算1人次

**示例**：
假设本月有3个已批准的请假申请：
- 申请1：2024-01-05 至 2024-01-07（3天）→ 1人次
- 申请2：2024-01-10 至 2024-01-10（1天）→ 1人次
- 申请3：2024-01-25 至 2024-01-27（3天）→ 1人次
- **本月请假人次**：3人次（不是7天）

#### 5.4.2 个人界面：统计天数（日期跨度）
```java
private int calculateLeaveDaysCount(Integer employeeId, LocalDate startDate, LocalDate endDate) {
    // 计算请假申请在统计范围内的实际天数
    // 1. 找到与统计范围有重叠的请假申请
    // 2. 计算重叠部分的天数
    // 3. 对所有重叠天数求和
}
```

**关键点**：
- 统计的是**天数**（日期跨度），不是人次
- 计算请假日期与统计范围的重叠部分天数
- 如果请假跨月，只统计统计范围内的天数
- **只用于单个员工查询**（`employeeId != null`）

**计算逻辑**：
```java
// 计算重叠部分的天数
LocalDate overlapStart = appStartDate.isBefore(startDate) ? startDate : appStartDate;
LocalDate overlapEnd = appEndDate.isAfter(endDate) ? endDate : appEndDate;
long days = ChronoUnit.DAYS.between(overlapStart, overlapEnd) + 1;  // +1 包含结束日期
totalDays += days;
```

**示例**：
假设本月有2个已批准的请假申请，统计范围：2024-01-01 至 2024-01-15
- 申请1：2024-01-05 至 2024-01-07（3天）→ 3天（全部在范围内）
- 申请2：2024-01-10 至 2024-01-20（11天）→ 6天（只统计 2024-01-10 至 2024-01-15）
- **本月请假天数**：3 + 6 = **9天**

### 5.5 个人界面 vs 管理员界面

| 特性 | 个人界面 | 管理员界面 |
|------|---------|-----------|
| 计算方式 | 天数（日期跨度） | 人次（申请次数） |
| 使用字段 | `leaveDays`（被覆盖为天数） | `weekLeaveDays`/`monthLeaveDays`（人次） |
| 显示单位 | 天 | 人次 |
| 计算方法 | `calculateLeaveDaysCount()` | `calculateLeaveDays()` |
| 适用场景 | 员工查看自己的请假总天数 | 管理员查看请假申请次数 |
| 触发条件 | `employeeId != null`（单个员工查询） | `employeeId == null`（部门或全部查询） |

## 六、补卡次数计算

### 6.1 数据来源
- **表**：`application`（申请表）
- **申请类型**：`REISSUE`（补卡）
- **状态**：`APPROVED`（已批准）

### 6.2 查询逻辑
与请假查询逻辑相同，只是过滤条件改为：
```java
.filter(app -> "REISSUE".equals(app.getApplicationType()))
```

### 6.3 时间过滤逻辑（重要）
```java
.filter(app -> app.getApproveTime() != null)  // 必须有审批时间
.filter(app -> {
    LocalDate approveDate = app.getApproveTime().toLocalDate();
    // 按审批时间统计，而不是补卡时间
    return !approveDate.isBefore(startDate) && !approveDate.isAfter(endDate);
})
```

**关键点**：
- 使用**审批时间（ApproveTime）**来判断是否在统计范围内
- **不是**使用补卡时间（ReissueTime）或申请创建时间
- 条件：`审批日期 >= 统计开始日期 且 审批日期 <= 统计结束日期`
- 必须存在 `ApproveTime`，否则不统计

### 6.4 计算方式
```java
.count();  // 统计申请次数
```

**关键点**：
- 统计的是**次数**（申请次数）
- 每个已批准的补卡申请算1次
- 按审批时间判断是否在统计范围内

### 6.5 示例
假设本月有2个已批准的补卡申请：
- 申请1：补卡时间 2024-01-10，审批时间 2024-01-12 → 1次（按审批时间统计）
- 申请2：补卡时间 2024-01-15，审批时间 2024-01-16 → 1次
- **本月补卡次数**：2次

## 七、查询范围处理

### 7.1 单个员工查询
```java
if (employeeId != null) {
    // 直接查询该员工的数据
    monthRecords = attendanceRecordDAO.findByEmployeeIdAndDateRange(employeeId, monthStart, now);
    overtimeApps = applicationDAO.findByEmployeeIdAndStatus(employeeId, "APPROVED");
}
```

### 7.2 部门查询
```java
else if (departmentId != null) {
    // 1. 查询部门下所有员工
    List<Employee> employees = employeeService.getEmployeesByDepartmentId(departmentId);
    
    // 2. 查询部门下所有员工的考勤记录（通过JOIN）
    monthRecords = attendanceRecordDAO.findByDepartmentIdAndDateRange(departmentId, monthStart, now);
    
    // 3. 遍历每个员工，查询其申请并合并
    for (Integer eid : employeeIds) {
        overtimeApps.addAll(applicationDAO.findByEmployeeIdAndStatus(eid, "APPROVED"));
    }
}
```

### 7.3 全部员工查询
```java
else {
    // 查询所有员工的记录
    monthRecords = attendanceRecordDAO.findAllByDateRange(monthStart, now);
    overtimeApps = applicationDAO.findAll()
        .stream()
        .filter(app -> "OVERTIME".equals(app.getApplicationType()))
        .filter(app -> "APPROVED".equals(app.getStatus()))
        .collect(Collectors.toList());
}
```

## 八、数据返回格式

### 8.1 返回字段

**工作时长**：
- `weekWorkHours`：本周工作时长（小时）
- `monthWorkHours`：本月工作时长（小时）

**加班时长**：
- `weekOvertimeHours`：本周加班时长（小时）
- `monthOvertimeHours`：本月加班时长（小时）
- `overtimeHours`：向后兼容字段（等于 `monthOvertimeHours`）

**请假**：
- `weekLeaveDays`：本周请假人次
- `monthLeaveDays`：本月请假人次
- `leaveDays`：向后兼容字段（等于 `monthLeaveDays`）

**补卡**：
- `weekReissueCount`：本周补卡次数
- `monthReissueCount`：本月补卡次数
- `reissueCount`：向后兼容字段（等于 `monthReissueCount`）

**其他**：
- `weekSummary`：周度汇总（正常、迟到、早退、缺卡等）
- `monthSummary`：月度汇总（正常、迟到、早退、缺卡等）

### 8.2 前端显示

前端根据 `viewType`（'week' 或 'month'）选择显示对应的数据：
```typescript
{viewType === 'week'
  ? stats.weekOvertimeHours
  : stats.monthOvertimeHours}
```

## 十一、常见问题

### Q1: 为什么请假统计的是人次而不是天数？
**A**: 因为业务需求是统计请假申请的次数，而不是请假的总天数。如果一次请假跨多天，也只算1人次。

### Q2: 补卡为什么按审批时间统计？
**A**: 因为补卡申请需要审批，只有审批通过后才生效。按审批时间统计可以更准确地反映补卡的实际发生时间。

### Q3: 如果一次请假跨月，会如何统计？
**A**: 如果请假的日期范围与统计月份有重叠，就会被统计。例如：
- 请假：2024-01-28 至 2024-02-05
- 1月统计：会被统计（因为 2024-01-28 在1月范围内）
- 2月统计：也会被统计（因为 2024-02-05 在2月范围内）

### Q4: 工作时长为0的记录会被统计吗？
**A**: 不会。只统计 `WorkHours` 不为 `null` 的记录。如果工作时长为0，该记录不参与统计。

### Q5: 待审批的申请会被统计吗？
**A**: 不会。只统计状态为 `APPROVED`（已批准）的申请。待审批（PENDING）、已拒绝（REJECTED）、已取消（CANCELLED）的申请都不会被统计。

## 十二、员工查询 vs 管理员查询

### 12.1 后端逻辑

**完全相同**：
- 使用同一个API端点：`GET /api/attendance/statistics`
- 使用同一个服务方法：`AttendanceService.getStatistics()`
- 计算逻辑完全相同，只是查询范围不同

### 12.2 查询范围

**员工查询**：
```java
// 前端固定传递 employeeId
employeeId = user.employeeId  // 只能查询自己的数据
departmentId = null
// 后端执行：
weekRecords = attendanceRecordDAO.findByEmployeeIdAndDateRange(employeeId, weekStart, now);
monthRecords = attendanceRecordDAO.findByEmployeeIdAndDateRange(employeeId, monthStart, now);
```

**管理员查询**：
```java
// 前端根据选择传递参数
if (selectedEmployeeId) {
    // 查询特定员工（与员工查询逻辑相同）
    employeeId = selectedEmployeeId
    departmentId = null
} else if (selectedDepartmentId) {
    // 查询部门下所有员工
    employeeId = null
    departmentId = selectedDepartmentId
    // 后端执行：
    weekRecords = attendanceRecordDAO.findByDepartmentIdAndDateRange(departmentId, weekStart, now);
    monthRecords = attendanceRecordDAO.findByDepartmentIdAndDateRange(departmentId, monthStart, now);
} else {
    // 查询全部员工
    employeeId = null
    departmentId = null
    // 后端执行：
    weekRecords = attendanceRecordDAO.findAllByDateRange(weekStart, now);
    monthRecords = attendanceRecordDAO.findAllByDateRange(monthStart, now);
}
```

### 12.3 前端显示差异

| 特性 | 员工查询 | 管理员查询 |
|------|---------|-----------|
| 查询范围 | 只能查询自己 | 可以查询任意员工/部门/全部 |
| 数据选择 | 固定显示月度数据 | 可根据 viewType 选择周度/月度 |
| 使用字段 | `overtimeHours`、`leaveDays`、`reissueCount` | `weekOvertimeHours`/`monthOvertimeHours` 等 |
| 页面组件 | `StatisticsPage.tsx` | `AdminAttendancePage.tsx` |

### 12.4 时间范围

**重要**：无论是员工查询还是管理员查询，时间范围的计算逻辑完全相同：
- **周度**：本周一 00:00:00 至 今天 23:59:59
- **月度**：本月1号 00:00:00 至 今天 23:59:59

例如：
- 如果今天是 2024-01-15（周一）
- 周度范围：2024-01-15 至 2024-01-15（只有今天）
- 月度范围：2024-01-01 至 2024-01-15（本月1号至今天）

## 十三、总结

1. **工作时长**：从考勤记录表统计，求和所有有工作时长的记录
2. **加班时长**：从申请表统计已批准的加班申请，按开始日期过滤，计算时长并求和
3. **请假**：
   - **个人界面**：统计请假天数（日期跨度），计算请假日期与统计范围的重叠部分天数
   - **管理员界面**：统计请假人次（申请次数），每个已批准的请假申请算1人次
4. **补卡**：从申请表统计已批准的补卡申请，按审批时间过滤，统计申请次数

**关键点**：
- **请假计算逻辑不同**：
  - 个人界面（单个员工查询）：使用 `calculateLeaveDaysCount()` 计算天数
  - 管理员界面（部门/全部查询）：使用 `calculateLeaveDays()` 计算人次
- 其他统计项（工作时长、加班、补卡）使用相同的计算逻辑
- 时间范围计算逻辑完全相同：周度=本周一至今天，月度=本月1号至今天

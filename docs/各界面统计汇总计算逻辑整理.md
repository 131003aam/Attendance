# 各界面统计汇总计算逻辑整理

## 一、界面概览

系统中有两个主要的统计汇总界面：

1. **个人统计汇总界面** (`StatisticsPage.tsx`)
   - 访问者：所有员工（包括管理员）
   - 查询范围：只能查询自己的数据
   - 显示方式：固定显示月度数据

2. **管理员考勤汇总界面** (`AdminAttendancePage.tsx`)
   - 访问者：仅管理员
   - 查询范围：可以查询任意员工/部门/全部员工
   - 显示方式：可根据 `viewType` 选择显示周度或月度数据

## 二、时间范围定义

### 2.1 周度统计
```java
LocalDate now = LocalDate.now();
LocalDate weekStart = now.minusDays(now.getDayOfWeek().getValue() - 1);
// 统计范围：本周一 00:00:00 至 今天 23:59:59
```

**示例**：
- 如果今天是 2024-01-15（周一），则 `weekStart = 2024-01-15`
- 如果今天是 2024-01-17（周三），则 `weekStart = 2024-01-15`（本周一）

### 2.2 月度统计
```java
LocalDate monthStart = LocalDate.of(now.getYear(), now.getMonth(), 1);
// 统计范围：本月1号 00:00:00 至 今天 23:59:59
```

**示例**：
- 如果今天是 2024-01-15，则 `monthStart = 2024-01-01`
- 统计范围：2024-01-01 至 2024-01-15

## 三、个人统计汇总界面 (`StatisticsPage.tsx`)

### 3.1 界面特点
- **查询范围**：固定为当前登录员工（`user.employeeId`）
- **时间范围**：固定为月度（本月1号至今天）
- **API调用**：`GET /api/attendance/statistics?employeeId={user.employeeId}&type=month`

### 3.2 显示的统计项

#### 3.2.1 本月工作时长
- **数据来源**：`attendance_record` 表
- **查询逻辑**：
  ```java
  monthRecords = attendanceRecordDAO.findByEmployeeIdAndDateRange(employeeId, monthStart, now);
  ```
- **计算方式**：
  ```java
  double monthWorkHours = monthRecords.stream()
      .filter(r -> r.getWorkHours() != null)  // 只统计有工作时长的记录
      .mapToDouble(r -> r.getWorkHours().doubleValue())
      .sum();  // 求和
  ```
- **显示**：`{stats.monthWorkHours.toFixed(1)} 小时`
- **关键点**：
  - 只统计 `WorkHours` 不为 `null` 的记录
  - 如果只有上班打卡没有下班打卡，该记录不参与统计

#### 3.2.2 加班时长
- **数据来源**：`application` 表（申请类型：`OVERTIME`，状态：`APPROVED`）
- **查询逻辑**：
  ```java
  overtimeApps = applicationDAO.findByEmployeeIdAndStatus(employeeId, "APPROVED");
  ```
- **时间过滤**：
  ```java
  .filter(app -> {
      LocalDate appDate = app.getStartTime().toLocalDate();
      return !appDate.isBefore(monthStart) && !appDate.isAfter(now);
  })
  ```
- **计算方式**：
  ```java
  .mapToDouble(app -> {
      long minutes = Duration.between(app.getStartTime(), app.getEndTime()).toMinutes();
      return minutes / 60.0;  // 转换为小时
  })
  .sum();  // 求和
  ```
- **显示**：`{stats.overtimeHours.toFixed(1)} 小时`
- **关键点**：
  - 使用申请的**开始日期**判断是否在统计范围内
  - 计算每个申请的时长并求和

#### 3.2.3 请假天数 ⭐（特殊逻辑）
- **数据来源**：`application` 表（申请类型：`LEAVE`，状态：`APPROVED`）
- **查询逻辑**：
  ```java
  leaveApps = applicationDAO.findByEmployeeIdAndStatus(employeeId, "APPROVED");
  ```
- **计算方法**：`calculateLeaveDaysCount()` - **计算天数（日期跨度）**
- **计算逻辑**：
  ```java
  // 1. 找到与统计范围有重叠的请假申请
  // 2. 计算重叠部分的天数
  for (Application app : leaveApps) {
      LocalDate appStartDate = app.getStartTime().toLocalDate();
      LocalDate appEndDate = app.getEndTime().toLocalDate();
      
      // 检查是否有重叠
      if (appEndDate.isBefore(monthStart) || appStartDate.isAfter(now)) {
          continue;  // 没有重叠，跳过
      }
      
      // 计算重叠部分
      LocalDate overlapStart = appStartDate.isBefore(monthStart) ? monthStart : appStartDate;
      LocalDate overlapEnd = appEndDate.isAfter(now) ? now : appEndDate;
      
      // 计算天数（包含开始和结束日期）
      long days = ChronoUnit.DAYS.between(overlapStart, overlapEnd) + 1;
      totalDays += (int) days;
  }
  ```
- **显示**：`{stats.leaveDays} 天`（注意：后端会将 `leaveDays` 字段覆盖为天数）
- **关键点**：
  - ⭐ **统计的是天数（日期跨度），不是人次**
  - 计算请假日期与统计范围的重叠部分天数
  - 如果请假跨月，只统计统计范围内的天数
  - **示例**：
    - 请假：2024-01-10 至 2024-01-20（11天）
    - 统计范围：2024-01-01 至 2024-01-15
    - 统计结果：6天（2024-01-10 至 2024-01-15）

#### 3.2.4 补卡次数
- **数据来源**：`application` 表（申请类型：`REISSUE`，状态：`APPROVED`）
- **查询逻辑**：
  ```java
  reissueApps = applicationDAO.findByEmployeeIdAndStatus(employeeId, "APPROVED");
  ```
- **时间过滤**：
  ```java
  .filter(app -> app.getApproveTime() != null)  // 必须有审批时间
  .filter(app -> {
      LocalDate approveDate = app.getApproveTime().toLocalDate();
      return !approveDate.isBefore(monthStart) && !approveDate.isAfter(now);
  })
  ```
- **计算方式**：
  ```java
  .count();  // 统计申请次数
  ```
- **显示**：`{stats.reissueCount} 次`
- **关键点**：
  - 使用**审批时间**判断是否在统计范围内（不是补卡时间）
  - 必须存在 `ApproveTime` 才会被统计

#### 3.2.5 月度汇总（正常、迟到、早退、缺卡）
- **数据来源**：`attendance_record` 表
- **查询逻辑**：同"本月工作时长"
- **计算方式**：
  ```java
  // 正常出勤：有checkInTime和checkOutTime且状态为NORMAL的记录数
  normalDays = (int) monthRecords.stream()
      .filter(r -> "NORMAL".equals(r.getStatus()))
      .filter(r -> r.getCheckInTime() != null && r.getCheckOutTime() != null)
      .count();
  
  // 迟到：状态为LATE的记录数
  lateDays = (int) monthRecords.stream()
      .filter(r -> "LATE".equals(r.getStatus()))
      .count();
  
  // 早退：状态为EARLY_LEAVE的记录数
  earlyLeaveDays = (int) monthRecords.stream()
      .filter(r -> "EARLY_LEAVE".equals(r.getStatus()))
      .count();
  
  // 计算从本月1号到当天的实际工作日数（周一到周五）
  long workDays = monthStart.datesUntil(now.plusDays(1))
      .filter(date -> {
          int dayOfWeek = date.getDayOfWeek().getValue();
          return dayOfWeek >= 1 && dayOfWeek <= 5; // 周一到周五
      })
      .count();
  
  // 缺卡：应出勤天数 - (正常+迟到+早退)人次
  // 应出勤天数 = 从本月1号到当天的实际工作日数（不再固定21天）
  missingDays = Math.max(0, (int)workDays - (normalDays + lateDays + earlyLeaveDays));
  ```
- **显示**：`{stats.monthSummary.normalDays} 人次` 等
- **关键点**：
  - ⭐ **月度统计不再使用固定的21天，而是使用从本月1号到当天的实际工作日数**
  - 工作日定义：周一到周五（不包括周末）
  - **示例**：
    - 如果今天是 2024-01-15（周一），本月1号到15号有11个工作日
    - 应出勤天数 = 11天（不是21天）

## 四、管理员考勤汇总界面 (`AdminAttendancePage.tsx`)

### 4.1 界面特点
- **查询范围**：可选择
  - 特定员工（`selectedEmployeeId`）
  - 特定部门（`selectedDepartmentId`）
  - 全部员工（都不选）
- **时间范围**：可选择周度或月度（`viewType: 'week' | 'month'`）
- **API调用**：
  ```typescript
  GET /api/attendance/statistics?type={viewType}&employeeId={selectedEmployeeId}&departmentId={selectedDepartmentId}
  ```

### 4.2 显示的统计项

#### 4.2.1 工作时长
- **数据来源**：`attendance_record` 表
- **查询逻辑**：
  ```java
  if (employeeId != null) {
      records = attendanceRecordDAO.findByEmployeeIdAndDateRange(employeeId, startDate, endDate);
  } else if (departmentId != null) {
      records = attendanceRecordDAO.findByDepartmentIdAndDateRange(departmentId, startDate, endDate);
  } else {
      records = attendanceRecordDAO.findAllByDateRange(startDate, endDate);
  }
  ```
- **计算方式**：同个人界面
  ```java
  double workHours = records.stream()
      .filter(r -> r.getWorkHours() != null)
      .mapToDouble(r -> r.getWorkHours().doubleValue())
      .sum();
  ```
- **显示**：
  ```typescript
  {viewType === 'week'
    ? `${stats.weekWorkHours.toFixed(1)} 小时`
    : `${stats.monthWorkHours.toFixed(1)} 小时`}
  ```

#### 4.2.2 正常出勤、迟到、早退、缺卡
- **数据来源**：`attendance_record` 表
- **查询逻辑**：同"工作时长"
- **计算方式**：
  ```java
  // 计算从startDate到endDate之间的实际工作日数（周一到周五）
  long workDays = startDate.datesUntil(endDate.plusDays(1))
          .filter(date -> {
              int dayOfWeek = date.getDayOfWeek().getValue();
              return dayOfWeek >= 1 && dayOfWeek <= 5; // 周一到周五
          })
          .count();
  
  // 单个员工查询
  if (employeeId != null) {
      normalDays = (int) records.stream()
          .filter(r -> "NORMAL".equals(r.getStatus()))
          .filter(r -> r.getCheckInTime() != null && r.getCheckOutTime() != null)
          .count();
      // ... 其他统计项类似
      
      int expectedDays;
      if (isMonth) {
          // 月度：使用从本月1号到当天的实际工作日数
          expectedDays = (int) workDays;
      } else {
          // 周度：计算实际工作日数，但最多5天
          expectedDays = (int) Math.min(workDays, 5);
      }
      
      // 缺卡人次 = 应出勤天数 - (正常+迟到+早退)人次
      missingDays = Math.max(0, expectedDays - (normalDays + lateDays + earlyLeaveDays));
  } else {
      // 部门或全部员工查询
      // 1. 计算所有员工的应打卡总次数
      int expectedDaysPerEmployee;
      if (isMonth) {
          // 月度：使用从本月1号到当天的实际工作日数
          expectedDaysPerEmployee = (int) workDays;
      } else {
          // 周度：计算实际工作日数，但最多5天
          expectedDaysPerEmployee = (int) Math.min(workDays, 5);
      }
      int totalExpectedCheckIns = expectedDaysPerEmployee * employees.size();
      
      // 2. 计算实际打卡次数
      int actualCheckIns = normalDays + lateDays + earlyLeaveDays;
      
      // 3. 缺卡人次 = 应打卡次数 - 实际打卡次数
      missingDays = Math.max(0, totalExpectedCheckIns - actualCheckIns);
  }
  ```
- **显示**：`{currentSummary.normalDays} 人次` 等
- **关键点**：
  - ⭐ **月度统计不再使用固定的21天，而是使用从本月1号到当天的实际工作日数**
  - 周度统计：计算实际工作日数，但最多5天
  - 工作日定义：周一到周五（不包括周末）

#### 4.2.3 加班时长
- **数据来源**：`application` 表（申请类型：`OVERTIME`，状态：`APPROVED`）
- **查询逻辑**：
  ```java
  if (employeeId != null) {
      overtimeApps = applicationDAO.findByEmployeeIdAndStatus(employeeId, "APPROVED");
  } else if (departmentId != null) {
      // 1. 获取部门下所有员工
      List<Employee> employees = employeeService.getAllEmployees();
      String deptIdStr = String.format("D%09d", departmentId);
      List<Integer> employeeIds = employees.stream()
          .filter(emp -> deptIdStr.equals(emp.getDid()))
          .map(Employee::getEid)
          .collect(Collectors.toList());
      
      // 2. 遍历每个员工，查询其申请并合并
      overtimeApps = new ArrayList<>();
      for (Integer eid : employeeIds) {
          overtimeApps.addAll(applicationDAO.findByEmployeeIdAndStatus(eid, "APPROVED"));
      }
  } else {
      // 查询所有员工的已批准加班申请
      List<Application> allApps = applicationDAO.findAll();
      overtimeApps = allApps.stream()
          .filter(app -> "OVERTIME".equals(app.getApplicationType()))
          .filter(app -> "APPROVED".equals(app.getStatus()))
          .collect(Collectors.toList());
  }
  ```
- **时间过滤**：同个人界面（使用申请的**开始日期**）
- **计算方式**：同个人界面（计算时长并求和）
- **显示**：
  ```typescript
  {viewType === 'week'
    ? `${stats.weekOvertimeHours.toFixed(1)} 小时`
    : `${stats.monthOvertimeHours.toFixed(1)} 小时`}
  ```

#### 4.2.4 请假 ⭐（特殊逻辑）
- **数据来源**：`application` 表（申请类型：`LEAVE`，状态：`APPROVED`）
- **查询逻辑**：同"加班时长"（根据查询范围选择不同的查询方式）
- **计算方法**：`calculateLeaveDays()` - **统计人次（申请次数）**
- **时间过滤**：
  ```java
  .filter(app -> {
      LocalDate appStartDate = app.getStartTime().toLocalDate();
      LocalDate appEndDate = app.getEndTime().toLocalDate();
      // 检查请假日期是否与统计范围有重叠
      return !appEndDate.isBefore(startDate) && !appStartDate.isAfter(endDate);
  })
  ```
- **计算方式**：
  ```java
  .count();  // 统计申请次数，每人每次申请算1人次
  ```
- **显示**：
  ```typescript
  {viewType === 'week'
    ? `${stats.weekLeaveDays} 人次`
    : `${stats.monthLeaveDays} 人次`}
  ```
- **关键点**：
  - ⭐ **统计的是人次（申请次数），不是天数**
  - 每个已批准的请假申请算1人次
  - 如果一次请假跨多天，也只算1人次
  - **示例**：
    - 申请1：2024-01-05 至 2024-01-07（3天）→ 1人次
    - 申请2：2024-01-10 至 2024-01-10（1天）→ 1人次
    - **本月请假人次**：2人次（不是4天）

#### 4.2.5 出差
- **数据来源**：`application` 表（申请类型：`BUSINESS_TRIP`，状态：`APPROVED`）
- **查询逻辑**：同"请假"（根据查询范围选择不同的查询方式）
- **时间过滤**：同"请假"（使用日期范围重叠判断）
- **计算方式**：
  ```java
  .count();  // 统计申请次数（人次）
  ```
- **显示**：
  ```typescript
  {viewType === 'week'
    ? `${stats.weekBusinessTripDays} 人次`
    : `${stats.monthBusinessTripDays} 人次`}
  ```

#### 4.2.6 补卡次数
- **数据来源**：`application` 表（申请类型：`REISSUE`，状态：`APPROVED`）
- **查询逻辑**：同"请假"（根据查询范围选择不同的查询方式）
- **时间过滤**：同个人界面（使用**审批时间**）
- **计算方式**：
  ```java
  .count();  // 统计申请次数
  ```
- **显示**：
  ```typescript
  {viewType === 'week'
    ? `${stats.weekReissueCount} 次`
    : `${stats.monthReissueCount} 次`}
  ```

## 五、关键差异对比

### 5.1 请假计算逻辑差异 ⭐

| 特性 | 个人界面 | 管理员界面 |
|------|---------|-----------|
| **计算方式** | 天数（日期跨度） | 人次（申请次数） |
| **计算方法** | `calculateLeaveDaysCount()` | `calculateLeaveDays()` |
| **使用字段** | `leaveDays`（被覆盖为天数） | `weekLeaveDays`/`monthLeaveDays`（人次） |
| **显示单位** | 天 | 人次 |
| **触发条件** | `employeeId != null`（单个员工查询） | `employeeId == null`（部门或全部查询） |
| **计算逻辑** | 计算请假日期与统计范围的重叠部分天数 | 统计在日期范围内有重叠的请假申请次数 |

**示例对比**：
- **请假申请**：
  - 申请1：2024-01-05 至 2024-01-07（3天）
  - 申请2：2024-01-10 至 2024-01-20（11天）
- **统计范围**：2024-01-01 至 2024-01-15
- **个人界面显示**：9天（3 + 6，申请2只统计到15号）
- **管理员界面显示**：2人次（2个申请）

### 5.2 其他统计项逻辑相同

| 统计项 | 个人界面 | 管理员界面 | 说明 |
|--------|---------|-----------|------|
| **工作时长** | ✅ 相同 | ✅ 相同 | 都从 `attendance_record` 表统计，求和 `WorkHours` |
| **加班时长** | ✅ 相同 | ✅ 相同 | 都从 `application` 表统计，按开始日期过滤，计算时长并求和 |
| **补卡次数** | ✅ 相同 | ✅ 相同 | 都从 `application` 表统计，按审批时间过滤，统计次数 |
| **出差** | ❌ 不显示 | ✅ 显示 | 管理员界面额外显示出差统计 |

### 5.3 时间范围差异

| 特性 | 个人界面 | 管理员界面 |
|------|---------|-----------|
| **时间范围选择** | 固定月度 | 可选择周度或月度 |
| **周度范围** | ❌ 不支持 | ✅ 本周一至今天 |
| **月度范围** | ✅ 本月1号至今天 | ✅ 本月1号至今天 |

```
    ↓
```

## 七、API 返回字段说明

### 7.1 个人界面使用的字段

```typescript
{
  monthWorkHours: number,      // 本月工作时长（小时）
```

## 八、常见问题

### Q1: 为什么个人界面和管理员界面的请假计算逻辑不同？
**A**: 
- **个人界面**：员工需要知道自己请了多少天假，所以统计天数（日期跨度）
- **管理员界面**：管理员需要知道有多少人次请假，所以统计人次（申请次数）

### Q2: 如果一次请假跨月，会如何统计？
**A**: 
- **个人界面**：只统计统计范围内的天数。例如：
  - 请假：2024-01-28 至 2024-02-05
  - 1月统计：3天（2024-01-28 至 2024-01-31）
  - 2月统计：5天（2024-02-01 至 2024-02-05）
- **管理员界面**：如果请假日期范围与统计月份有重叠，就会被统计。例如：
  - 请假：2024-01-28 至 2024-02-05
  - 1月统计：1人次（申请在1月范围内）
  - 2月统计：1人次（申请在2月范围内）

### Q3: 工作时长为0的记录会被统计吗？
**A**: 不会。只统计 `WorkHours` 不为 `null` 的记录。如果工作时长为0，该记录不参与统计。

### Q4: 待审批的申请会被统计吗？
**A**: 不会。只统计状态为 `APPROVED`（已批准）的申请。待审批（PENDING）、已拒绝（REJECTED）、已取消（CANCELLED）的申请都不会被统计。

### Q5: 补卡为什么按审批时间统计？
**A**: 因为补卡申请需要审批，只有审批通过后才生效。按审批时间统计可以更准确地反映补卡的实际发生时间。

## 九、总结

### 9.1 核心差异
1. **请假计算逻辑不同**：
   - 个人界面：统计天数（日期跨度）
   - 管理员界面：统计人次（申请次数）

2. **时间范围选择**：
   - 个人界面：固定月度
   - 管理员界面：可选择周度或月度

3. **查询范围**：
   - 个人界面：只能查询自己
   - 管理员界面：可以查询任意员工/部门/全部员工

### 9.2 相同点
- 工作时长、加班时长、补卡次数的计算逻辑完全相同
- 时间范围的计算逻辑完全相同（周度=本周一至今天，月度=本月1号至今天）
- 都使用相同的后端API和服务方法

### 9.3 关键代码位置
- **后端服务**：`src/main/java/com/attendance/management/system/service/AttendanceService.java`
  - `getStatistics()`: 主方法
  - `calculateLeaveDaysCount()`: 个人界面请假天数计算
  - `calculateLeaveDays()`: 管理员界面请假人次计算
  - `calculateOvertimeHours()`: 加班时长计算
  - `calculateReissueCount()`: 补卡次数计算
- **前端组件**：
  - `frontend/src/pages/StatisticsPage.tsx`: 个人统计汇总界面
  - `frontend/src/pages/admin/AdminAttendancePage.tsx`: 管理员考勤汇总界面
